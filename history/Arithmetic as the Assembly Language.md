# Arithmetic as the Assembly Language

Oct 18, 2026 · @Aye Me Mine

I have a very simple thesis, one short sentence. But before I can give it to you, you must learn a bit about how computer languages work. It’s like everything else really, embedded levels of organization. And therefore, it’s easy to understand. But you need to learn some terminology, if you don’t know it already, of course.

Virtually all software developers, even AIs, program in what we call "high-level" computer languages. They're labeled "high-level" because underneath each one live at least two other languages: assembly and binary. The binary language sits at the very bottom of the software stack and is the only language the computer can actually run. It's literally just ones and zeros and is completely incomprehensible to humans, as you can well imagine. But assembly language is not incomprehensible. It sits between binary language and the high-level languages, and it has semantics like "move", "add", and "jump". Assembly is hard to code in because it's written in terms of the specific hardware the computer has been built with. And therefore, the assembly language programmer starts by learning all the details of the chip, which is little more than a tiny workbench sparsely populated with the handful of tools and storage locations the hardware provides. To program in assembly is high art; it's juggling names and places; it’s remembering where things are and why. Which explains the need for high-level languages: they transport the programmer into a fantasy land in which all resources are seemingly unlimited, allowing them to focus on a higher level of juggling.

Summarizing then, because assembly language sits down there juggling chainsaws on our behalf, we get to juggle bean bags in our high-level languages. Now, when we're absolutely sure we've got our high-level program's logic all worked out, we “compile” it. And when we do, our high-level program gets rewritten in assembly, which is then rewritten in binary, which the computer can then run. Compilation never changes the logic, only the form. So compilation gives us three programs that do exactly the same thing.

(And, as an aside (a public service announcement really) when we run the program, it almost invariably and immediately does something stupid. So we try again. And again. And again. And again. All day long. It sounds awful, doesn’t it? But if you’re self-observant enough that you’ve realized your core problem in life is that you can't stand other people, do look into coding!!! It's hard, but at least it makes sense! You can work with it. And I’m sure vibe coding will be the same thing, still thinking logically, just at yet a higher level.)

OK. Now that you’re clear on what an assembly language is, I can state my thesis: Arithmetic is the assembly language for modern physics. Literally. The universe is a computer we’re inside of, and its stack lines up with ours, layer for layer. At the bottom, playing the part of binary, is something, (first-order logic?), as unreadable in raw form as any string of ones and zeros. Above it sits arithmetic, our assembly language: whole numbers only, and a handful of operations on them. And on top assembly sits modern physics, our high-level language, a fantasy land of unlimited precision where everything is smooth and continuous. Whenever anyone actually computes anything in physics, it gets compiled down into arithmetic, and arithmetic down into logic. And remember, compilation never changes the logic, only the form. So physics and arithmetic aren’t related the way a building is related to its bricks. They are the same program, written twice.

Now, we also know that it has been proven (William Rowan Hamilton, 1837) that the complex plane can be done with plain arithmetic. And since basically all of physics is done in the complex plane, we know that all of physics can be done in arithmetic. The only parts arithmetic can’t handle are exactly those parts where they sprinkle their continuous, infinite, magic dust over the arithmetic to get the answers.

So, we know, yes know, that physics can be compiled down to arithmetic. We don’t know if or how it is yet, but we know that it can be. We just have to run the magic dust in reverse.

So where does that put us? With a very strong argument for there being an arithmetic level which is serving as an assembly language. And with that, we have a touchstone for judging any new physics theory we write. We can always ask ourselves, is that how an assembly language would do it? Or be designed? We don’t have to sign off on the first math explanation that gives the right answers and hold onto it as sacred text until the end of time.

We can *believe* that we’re inside a computer, that physics is a high-level language that gets compiled into an assembly language, which is mathematics. And we can use that belief to navigate our ship as our North Star. Whenever we argue that this design or this solution is better than others, we’ll judge which wins by which better fits the assembly language design and implementation.
